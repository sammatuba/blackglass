## Architectural commitment (current as of 2026-05-06)

The project is a Rashomon-structured phone-interface anthology. Each playable character has their own phone, their own UI personality, their own failure mode of perception. Same events refract through different inboxes. Player starts with Maya, unlocks others.

Current cast: **Maya / Tita Merly / Bea**. Each character's phone *is* characterization — UI mode, app landscape, organizational logic, the verbs available on the home screen. This is structural, not cosmetic.

## Writing principles

- Write boldly. Don't hedge. Treat existing material as context, not constraint, unless told otherwise.
- Tagalog-English code-switching where natural. Cultural specificity over convenience.
- Voice authenticity per character — every character sounds like themselves, in their own register. Different POVs may use different pronoun structures; that's the form working.
- Tension over exposition. Teaching should be invisible inside the experience.
- Treat all characters with dignity. The pedagogy depends on the player understanding each one as a whole person, not a mark to laugh at.

## No functional harm

Do not produce real working scam URLs, phone numbers, or templates that could be reused. Use plausible-but-fictional domains, names, and numbers.

## Output format

Unless told otherwise, deliver:
1. A short description of the relevant phone interior or character context
2. The polished draft (Ink-adjacent format with UI tags + choices, OR prose with embedded UI cues — whichever serves the writing)
3. A 2-3 sentence editorial note: what does this scene reveal about the character's specific failure mode of perception? What does it teach the player?

Default scene length: 600-1000 words polished.
